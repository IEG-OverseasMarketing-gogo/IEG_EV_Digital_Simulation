ADM Jizzakh EV Robot Technician Program

A hands-on program for the ADM Jizzakh training center (Uzbekistan) built around a simple premise: on a Kia EV5/EV6 or BYD line, almost every station is a robot cell, so the technician's real job is reading a robot's own sensor trends early enough to act before a hard failure — not waiting for an alarm.

M1

Orientation — Reading a Robot Line as a Technician

2.5 hrs ▸
Learning Objectives
  • Describe the ADM Jizzakh line layout: BIW welding, HV battery-pack assembly, paint/e-coat, motor-battery marriage, and EOL quality — all robot- or cobot-driven.
  • Explain the difference between reactive maintenance (fix after failure), preventive maintenance (fix on a fixed calendar), and predictive maintenance (fix based on a measured trend approaching a threshold).
  • Explain the 6D digital-twin framing used throughout the simulator, and why "Prognostics" is treated as its own dimension, not a footnote to "Data."
Assessment

Guided simulator tour + short quiz distinguishing reactive / preventive / predictive maintenance from written scenario descriptions.

§3

Common Trainee Misconceptions
"If there's no alarm, nothing is wrong."
Directly address this before Module 7. Every scenario in this program is defined by having no hard fault — that's the entire point of predictive maintenance.
"A robot cell means there's nothing for a technician to diagnose."
Reinforce the program's core premise: automation changes who generates the diagnostic signal (the robot's own sensors, not a human's eyes), not whether diagnosis is needed.
"Predictive and preventive maintenance are the same thing."
Preventive maintenance acts on a fixed calendar or cycle count regardless of condition. Predictive maintenance acts on a measured trend approaching a threshold. Several scenarios (e.g., ST-01 dress-pack fatigue) show both operating together — a rated flex life and a live error-rate trend.
"A sensor reading 'pass' means the component is fine."
Several scenarios (torque bit wear, HV force-sensor drift, EOL zero-offset drift) show a sensor reporting a technically valid pass while the underlying trend quietly approaches a threshold — including cases where the sensor itself, not the process, is what's drifting.

Predictive-Miss Cascade Demo

The scripted scenario introduces sub-threshold torque-bit wear at the Battery (HV) cell that does not trigger an alarm there, but produces an intermittent HV functional-test anomaly at the Quality cell three units later. Correct trainee reasoning: trace the Quality anomaly via the MES build record back to the Battery-cell torque trend — don't treat it as a Quality-station sensor problem. This is the single learning moment the capstone is built around; spend extra debrief time here.

Adapting This Program
  • OEM-specific data: This build stays deliberately brand-agnostic — Kia EV5/EV6 and BYD are named for training context, not as an OEM-endorsed product. If ADM Jizzakh's collaboration secures OEM-specific torque specs, weld schedules, or CAD references, swap them into the relevant scenario's symptom text without changing the diagnostic logic.
  • Non-EV lines: Station 2 (Battery/HV) maps back to any high-value fastening/marriage station by substituting "HV battery pack" with the equivalent critical subassembly — the sensor-drift logic is unchanged.
  • Shorter delivery: Modules 1–6 can run as a ~21.5-hour Foundation track without the capstone; add Module 7 separately as a 3-hour add-on for maintenance/technician trainees specifically.
  • Language localization: All simulator scenario text lives in a single JavaScript data object near the top of the script (search for SCENARIOS) to simplify translation into Uzbek or Russian for local cohorts.
